# Contents

# 1\. Introduction

## 1.1 Purpose

This document defines the requirements for modifying and creating statutory ledgers and business reports needed for OwnersBook+ to handle digital securities (security tokens, "ST") under the beneficiary certificate issuing trust ("JS"; 受益証券発行信託) scheme.

Within the project plan scope "Customer sites and reports," this document covers reports. Screens are covered in the separate volume "Requirements Definition (Screen Changes)."

## 1.2 Background

The current OwnersBook+ statutory ledgers ("電子記録移転有価証券表示権利等 法定帳簿": 28 categories, 78 sheets) are **built only for the silent partnership (GK-TK) and voluntary partnership (NK) schemes**. Handling JS-scheme STs changes the following assumptions, so the current ledgers cannot be used as is.

| **Aspect**                             | **Current (TK type)**                                                                                                    | **JS type**                                                                                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Type of right                          | Silent partnership interest (electronically recorded transferable rights; Paragraph 2 security)                          | Beneficial interest / beneficiary certificate (electronically recorded transferable securities-representing rights, etc.; Paragraph 1 security) |
| Parties                                | Operator (godo kaisha / LLC)                                                                                             | Settlor SPC, trustee (trust company)                                                                                                            |
| Income category of distributions       | Miscellaneous income. 20.42% income tax withheld; local tax 0                                                            | Dividend income (withheld). The return-of-principal portion is subject to deemed transfer gain/loss calculation                                 |
| Income category of redemptions / sales | Miscellaneous income                                                                                                     | Capital gains (separate self-assessment). No withholding for general accounts; customers file tax returns                                       |
| Payment record                         | Payment record of profit distributions under silent partnership agreements (320), filed in bulk at the start of the year | Payment record of distributions of investment trusts or specified beneficiary certificate issuing trusts, filed within 1 month of payment       |
| Holder management                      | ST register (investor list)                                                                                              | Beneficiary register (Trust Act Art. 186). Records on Progmat are treated as the register                                                       |
| Balance reconciliation counterpart     | Loadstar Chain (in-house blockchain)                                                                                     | Progmat (JS type is not linked to Loadstar Chain)                                                                                               |
| Base price                             | Calculated by the operator                                                                                               | Net asset value of trust property per unit, calculated by the trustee                                                                           |

# 3\. How Reports Are Created Today

Based on "Ledger Creation Flow & Related APIs (Technical Guide)," this chapter summarizes how the current system creates statutory ledgers. The JS work builds on this mechanism, which determines the units of change and the points to watch.

## 3.1 Two Kinds of "Ledger"

In OwnersBook+, "ledger" refers to two completely separate mechanisms. **Report (PDF) creation does not read the blockchain directly and does not write to it.**

| **Category**       | **Type A: Statutory ledgers**                                                                                | **Type B: Distributed ledger (Loadstar Chain)**                                                                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| What it is         | Books required by the Financial Instruments and Exchange Act, etc. Static PDF/CSV files                      | Token records on GoQuorum (an Ethereum-compatible private blockchain). Issuance, transfer, and redemption recorded under ERC-1400 (a security token standard) |
| How it is produced | Scheduled batches (st-cli), e.g., at night, read MySQL transaction tables, create PDFs, and store them in S3 | Smart contracts record in real time. A sync process copies data into DB cache tables (bc_blocks, bc_tokens, etc.)                                             |
| Where it is viewed | Admin screen (st-admin) folder listing; customers via electronic delivery (trading site)                     | Blockchain explorer (st-bc-explorer)                                                                                                                          |
| Role               | Legal books for regulators (in yen, in beneficiary names)                                                    | Technical record of token state                                                                                                                               |
| Reconciliation     | Reconciliation batches outside Type A (e.g., Bt020) compare DB balances with on-chain holdings               | Same as left                                                                                                                                                  |
| JS handling        | JS type also uses this mechanism (scope of this document)                                                    | JS type is not linked. Its reconciliation counterpart is Progmat                                                                                              |

## 3.4 Points to Watch in the Current Mechanism

- **On non-business days and non-month-end days, batches exit normally without creating files.** On holidays they log OK(CLOSING) and exit with code 0, so "normal exit" does not always mean a PDF was produced.
- **Missing threshold settings cause abnormal termination.** RT003 stops with an exception if customer-count or page-count thresholds are missing from ESYS_CONFIG. New batches and new environments need these registered.
- **Insufficient permissions produce 0-byte PDFs.** Without execute permission or write permission on the output folder, FastPDFGen silently creates empty files. Watch for this when building the dedicated JS environment.
- **Work files are deleted.** On normal completion the work folder is removed, so files for investigation remain only after abnormal termination.
- **"Operator portion" is switched by an argument.** RT003 outputs the operator portion with argument 2, reversing debit/credit. How to output the JS settlor SPC / trustee portion will be designed after the scheme type (D-01) and trust account attributes (D-02) are decided.

# 6\. Non-functional Requirements

| **Category**          | **Requirement**                                                                                                                                                                                                                                                      |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Maintainability       | Manage product-type branching centrally in the product type master / report branching definition (N-16); do not hard-code it in each report. Hold tax rates and terms as parameters and mappings.                                                                    |
| Compatibility         | Do not change TK- and NK-type report output. Run regression tests comparing existing report output before and after changes.                                                                                                                                         |
| Accuracy / control    | Reconcile balances between our DB and Progmat daily and keep results and difference corrections as a report (N-17).                                                                                                                                                  |
| Deadline compliance   | Set processing timing so payment records can be filed within 1 month of payment and resident tax paid by the 10th of the following month.                                                                                                                            |
| Retention             | Keep statutory ledgers for the legally required periods. Keep the records we need without depending on Progmat's retention period (finalize after SP answer No. 12).                                                                                                 |
| Output format         | Output in PDF and CSV as today. Follow current output timing per report (daily, monthly, on occurrence, etc.). Align PDF splitting (per 1,000 customers or page limit) with the current method.                                                                      |
| Monitoring            | Do not judge success by exit code alone. To distinguish holiday skips (OK(CLOSING)) from actual output, check the number of outputs, file presence, and non-zero file size, and detect anomalies.                                                                    |
| Access control        | The admin report folders (/report_manage/, /report_customer/) are configured to show folder listings. Since reports containing personal data (beneficiary register, payment records, etc.) will increase, confirm who can access them and the authentication method. |
| Personal data         | Reports containing personal data, such as the beneficiary register and payment records, follow the same access control and handling as current statutory ledgers.                                                                                                    |
| Regulatory compliance | Layouts and items are based on requirements confirmed by LSEC's compliance department and the tax advisor (risk mitigation in the project plan).                                                                                                                     |
| Test environment      | Develop and test in the dedicated JS test environment (AWS). When building it, check FastPDFGen execute permission, output folder write permission, and ESYS_CONFIG thresholds (missing ones cause 0-byte PDFs or abnormal termination).                             |
