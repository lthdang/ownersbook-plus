単体テスト追加 E: メールアドレスのマスク表示（common.js regEmail）

# 詳細

## 背景

`src/utils/common.js` の関数に単体テストを追加する Phase 1 の E チケット（A〜E の5チケット構成、A: [HASHST\_DEV-4541](file:///view/HASHST_DEV-4541)、B: [HASHST\_DEV-4542](file:///view/HASHST_DEV-4542)、C: [HASHST\_DEV-4543](file:///view/HASHST_DEV-4543)、D: [HASHST\_DEV-4544](file:///view/HASHST_DEV-4544)）。

画面上でメールアドレスの一部を `*` で隠す `regEmail` が対象（呼び出し箇所 16）。関数は1つだけだが、マスクの仕方が崩れると個人情報がそのまま表示されるため、独立したチケットにしている。

## 前提

-   [HASHST\_DEV-4526](file:///view/HASHST_DEV-4526) が完了していること
-   Jest 22 のため `test.each` は使えない。テーブル駆動は素の `forEach` で書く
-   **現状の挙動を記録するテスト（characterization test）として書く**。疑わしい挙動が見つかっても本チケットでは修正せず、現状の挙動をコメント付きで記録し、別チケットに切り出す

## 現状の挙動（コードから読み取れる範囲）

-   `@` より前（ローカル部）が4文字以上: 先頭2文字と末尾1文字を残し、間を `*` に置き換える
-   ローカル部が3文字以下: **マスクせずにそのまま返す**
-   空の入力: 空文字を返す

## 確認すべき観点

-   ローカル部の文字数の境界（3文字 / 4文字）
-   ローカル部が3文字以下のときマスクされないのは意図した仕様か（仕様でなければ別チケットに切り出す）
-   `@` を含まない文字列、`@` が複数ある文字列
-   `null` / `undefined` / 空文字の入力

## 作業内容

-   `test/unit/specs/utils/common.regEmail.spec.js` を追加する
-   疑わしい挙動が見つかった場合は別チケットを起票し、本チケットにリンクする

## 完了条件

-   `regEmail` の spec があり、`npm run unit` が終了コード 0 で完了する
-   MR のパイプラインで `unit_test` ジョブが成功している
-   ローカル部が3文字以下の扱いについて、仕様確認の結果が本チケットにコメントされている

## 影響範囲

-   変更は `test/` 配下のみ。`src/` 配下の変更なし

## 本チケットに含めないこと

-   疑わしい挙動の修正 → 別チケット

## 備考

-   **テストには実在のメールアドレスを使用しない。** ドメインは `example.com` など、RFC 2606 で予約された例示用ドメインを使う
