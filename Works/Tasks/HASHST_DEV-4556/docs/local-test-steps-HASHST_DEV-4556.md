# HASHST_DEV-4556 ローカル確認手順（MR 添付用エビデンス）

対象：app-vuejs `verifyInputText`（入力文字種チェック）で範囲外の漢字を許可する変更
ブランチ：`backlog/HASHST_DEV-4556`（比較元：`f68dad7d` = `origin/js-ph2`）

MR には、各ケースの **修正前**（`f68dad7d`）と **修正後**（`backlog/HASHST_DEV-4556`）のスクリーンショットを添付する。

---

## 0. 先に共有：ローカル DB では「𠮷」を保存できない（確認済み）

ローカルの MySQL（`st-mysql`）で次のことを確認した。

- `hhd` / `basis` などのスキーマのテキスト列は**すべて `utf8mb3`（3バイト）**。顧客情報の `ECO_USER`・`ECO_USER_CHANGE`・`ECO_USER_REQUEST` の `NAME`・`ADDRESS1〜4`・`EMPLOYMENT` なども同じ
- `sql_mode` に `STRICT_TRANS_TABLES` があり、common-front-api の DB 接続も `strict => true`
- 一時テーブル（`utf8mb3` 列）で確認した結果：
  - 「山﨑」「㐂」（3バイト）は保存できる
  - 「𠮷田」（4バイト）は `ERROR 1366 Incorrect string value` になる

そのため、`checkJpText`（SJIS-win チェック）を呼ばない画面で「𠮷」を入力して送信すると、**サーバー側で DB エラーになる見込み**。修正前はフロントの書式エラーで止まっていたため、エラーの出方が変わる。結果は下記 **ケース B-1** で必ず記録する（ADR 0002 の「4バイト文字が保存できなければ見直す」に該当する）。

## 1. 準備

### 1-1. 環境

1. local-docker のコンテナを起動する（`st-mysql`、`st-web`、common-front-api / passport / st-front-api）
2. app-vuejs の `.env` が local の API を向いていることを確認する（`VUE_APP_COMMON_API` / `VUE_APP_PASSPORT_API` / `VUE_APP_FUND_API` が `local-*`）
3. `npm run dev` で起動する（port 8080）。OpenSSL エラーが出るときは `NODE_OPTIONS=--openssl-legacy-provider` を付ける
4. ブラウザは Chrome の **デバイスエミュレーション（スマートフォン）** で開く
   - PC の UA だと、お名前（l2212）・国籍（l2213）が QR コード画面（`/l2325`）に飛ばされる
   - l2212・l2213 の送信ボタンでも PC 向けのアラートが出る

### 1-2. 修正前と修正後の切り替え


`config/dev.env.js` のローカル向けの変更（未コミット）はそのまま残る。コミットしないこと。

### 1-4. 入力する文字

| 入力値 | 文字 | 3段階のチェックの見込み |
| --- | --- | --- |
| `髙橋` | 髙 U+9AD9（範囲内、対照用） | 修正前・修正後とも通る |
| `山﨑` | 﨑 U+FA11（CJK 互換漢字、3バイト） | ① 修正後に通る → ② SJIS-win 可 → DB 保存可 |
| `㐂` | U+3402（拡張 A、3バイト） | ① 修正後に通る → ② SJIS-win **不可** → DB 保存可 |

### 1-5. エラー文言

- **書式エラー**：画面ごとに異なる（下記の各ケースに記載）。入力欄の下に赤字で出る
- **SJIS-win エラー**（`checkJpText`、E103-1045）：「{文字}の入力はできません。ひらがなで入力してください。」。フォーカスを外したとき（blur）に出る。その欄に書式エラーがあるときは呼ばれない

## 2. 確認ケース

優先度 **A** は必須。**B** は A と同じ仕組みの画面のため、時間があれば確認する。

スクリーンショットのファイル名は `<ケースID>_<before|after>_<入力値>.png`（例：`A-1_after_山﨑.png`）。

### A-1. 個人：お名前（l2212）— 書式チェック ＋ SJIS-win チェックあり

**手順**

1. 個人アカウントでログイン → マイページ → 設定（`/l2100`）→「お客様情報の確認・変更」→ 取引暗証番号を入力 → `/l2200`
2. 「お名前」カードの「変更」→ `/l2212`。「情報の変更」を選ぶ
3. **お名前（全角）「姓」**に下表の値を入力し、「名」の欄をクリックしてフォーカスを外す
4. 表示を撮影する

| 入力（姓） | 修正前 | 修正後 |
| --- | --- | --- |
| `髙橋` | エラーなし | エラーなし |
| `山﨑` | 「姓を正しく入力してください。」 | **エラーなし** |
| `㐂` | 「姓を正しく入力してください。」 | 「㐂の入力はできません。ひらがなで入力してください。」 |
| `𠮷田` | 「姓を正しく入力してください。」 | 「𠮷の入力はできません。ひらがなで入力してください。」 |
| `山田😀` | 「姓を正しく入力してください。」 | 「姓を正しく入力してください。」 |

5. 住所の **市区町村・町域名**（type3）・**番地**（type7）・**建物名・部屋番号等**（type3）でも、`山﨑町` / `㐂` / `𠮷田` を入力して同じように確認する
   - 修正前の書式エラー：「漢字/ひらがな/全角カタカナ/数字/英字/ー/-/空白スペースを入力してください。」
6. （任意）姓「山﨑」で送信すると、外部の eKYC へ遷移する。ローカルで eKYC が動くかは未確認のため、DevTools の Network で `/user/ekyc_url` のリクエストの `NAME` に「山﨑」が入っていることを撮影すれば十分

### B-1. 個人：職業（l2216）の送信 — 4バイト文字の保存（**必須**。§0 の確認）

修正後のみ実施する。

1. A-2 の画面で勤務先名 `山﨑商事` を入力して送信し、取引暗証番号を入力する → `/l2203`「変更が完了しました」になることを撮影する
2. もう一度 l2216 を開き、勤務先名 `𠮷田商事` で送信する
3. 次の3点を記録する
   - 画面の表示（エラーのアラート・画面遷移の有無）
   - DevTools の Network で `/user/job` のステータスコードとレスポンス
   - common-front-api のログ（`storage/logs/`）に `SQLSTATE[HY000]: General error: 1366 Incorrect string value` が出ているか
4. 後片付け：勤務先名を元の値に戻して送信する

**見込み**：手順 1 は成功する。手順 2 は DB エラー（1366）でサーバーエラーになる。
見込みどおりなら、MR と Backlog に記録したうえで方針を相談する（§3 を参照）。
